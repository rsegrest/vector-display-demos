vector-display: a live guide

The @vector-display packages draw graphics the way a vector arcade monitor did: as glowing lines traced by a beam, not as a grid of pixels. Every example on this page is running. Change the code and the display beside it redraws as you type.

Beam settings

These change every display on the page, and are remembered for next time.

The beam

A vector display has three properties an ordinary screen does not have by default. Light is additive: where lines cross, they get brighter. The phosphor has persistence: a moving beam leaves a trail that fades. And there are only lines: nothing is ever filled in.

The packages split the work in the same way the hardware did. @vector-display/core holds shapes and the list of strokes to draw this frame. @vector-display/webgl draws that list. @vector-display/beam-fx adds the phosphor. @vector-display/font and @vector-display/3d make strokes from text and from wireframe models.

The display list

A DisplayList is the list of strokes for one frame. You clear it, set a colour, and add shapes; then a renderer draws it. Nothing is kept from one frame to the next, so a program rebuilds the list every frame. It reuses its memory, so that costs very little.

Coordinates are world units, with the origin at the top left and y pointing down, as in Canvas 2D. The renderer maps whatever world size you choose onto the canvas.

Shapes

A Shape is line geometry, made once and placed as often as you like. There are four ways to make one.

  • Shape.fromPolyline(polyline): a run of points. With isClosed: true it joins back to the first point.
  • Shape.fromPolylines(polylines): several runs in one shape, for anything with separate strokes.
  • Shape.fromSegmentCoordinates([x0, y0, x1, y1, ...]): raw segments, four numbers each. Segments that touch end to start are treated as connected.
  • Shape.createDot(): a segment of no length, which draws as a round dot, like a bullet on a vector monitor.

Whether segments are connected matters to how they look. The beam is brighter where it starts and stops, and a renderer can either show that at every corner or join the corners seamlessly. See line style.

Placement

Each call to addShape takes a placement: where the shape goes (x, y), how far it is turned (rotation, in radians, clockwise on screen because y points down), how large it is (scale), and how bright (intensity). One shape can be placed many times in a frame.

For geometry that is already in world coordinates, pass SCREEN_SPACE_PLACEMENT, which is no movement, no rotation, a scale of 1 and an intensity of 1.

Colour and brightness

setColor takes red, green and blue from 0 to 1, and applies to every shape added after it. Light adds up: where two lines cross, the crossing is brighter than either, and where red, green and blue lines meet, the meeting point is white. Intensity above 1 is allowed, and is how you make something burn.

Geometry made every frame

A Shape is for geometry that does not change. For geometry that does (a waveform, a contour, a swarm) the display list accepts anything with the ShapeGeometry interface, so you can fill your own buffers each frame and avoid making new objects:

  • segmentCoordinates: a Float32Array with four numbers per segment, x0, y0, x1, y1.
  • segmentNeighbors: an Int32Array with two numbers per segment: the index of the segment it continues from and the index of the one that continues it, or NO_NEIGHBOR_SEGMENT (-1) at a loose end.
  • segmentCount: how many segments are in use. The buffers may be longer.

Line style

WebGLVectorRenderer draws a whole display list in one draw call. How its lines look is set with renderer.setLineStyle({ ... }), in framebuffer pixels:

FieldDefaultEffect
beamWidth1.5Width of the line itself
glowRadius4How far the soft halo round each line reaches
glowStrength0.25How bright that halo is
endpointBrightness0.6Extra brightness where a stroke starts and stops; 0 removes it
jointOverlap1Extra brightness where connected segments meet; 0 gives seamless joints

The first three are in the beam settings panel. The last two are a choice about character: a real beam dwells at the ends of each stroke, which gives arcade vector graphics their beaded corners.

Phosphor

PhosphorPipeline sits on top of the renderer and gives the display its glass. In place of clearing and drawing, you call phosphor.renderFrame(displayList, elapsedMilliseconds): it draws the beams, fades what was there before, adds bloom, and writes the result to the canvas.

SettingDefaultEffect
persistenceHalfLifeMilliseconds40How long a trail takes to fade to half brightness
bloomStrength1.2The wide glow round bright lines; lower looks crisper
bloomBlurIterations2How far that glow spreads
exposure1.6How quickly bright areas roll off toward white
flickerAmount0.08Depth of the random brightness flutter, 0 to 1
flickerFrequencyHz15How often the flutter changes level

The effects are based on time, not frames, so they look the same at 60 Hz and at 120 Hz. Something that does not move keeps its true brightness; only movement leaves a trail. That makes persistence a drawing tool: draw only a moving point, and the phosphor draws the path.

Photosensitivity: strong full-screen flicker at around 3 to 30 Hz can trigger seizures in people with photosensitive epilepsy. Keep flickerAmount small, and let people turn it off. The panel on this page stops at 0.15.

Text

@vector-display/font is a stroke font in the style of late-1970s vector games, drawn on a 4 by 6 grid, and a small text layout. Letters are beam strokes like everything else, so they glow and leave trails like everything else.

font.addText(displayList, run) takes text, x, y (the top of the first line), size (the height of a capital, in world units), and optionally alignment ("left", "center" or "right"), rotation and intensity. font.measureText(text, size) gives the width and height it would take. The font has A to Z, 0 to 9 and common punctuation; lowercase is drawn as capitals, and \n starts a new line.

With glow and bloom, text 16 units tall or more reads clearly. For smaller text, turn bloom and endpoint brightness down. You can add or replace glyphs with VectorFont.createArcadeFont({ ... }), or build a whole font with VectorFont.fromDefinition.

Three dimensions

@vector-display/3d projects wireframe models into strokes. Its space has x to the right, y up, and z away from the viewer; what comes out is in the display's own y-down coordinates. The maths types, Vector and Angle, come from es-vector-math.

  • A model is vertices and the polylines that join them: WireframeModel.fromDefinition({ vertices, polylines }). createBoxModel and createPyramidModel are included.
  • A placement puts a model in the scene: createModelPlacement({ position, rotationX, rotationY, rotationZ, scale }), applied as scale, then rotation, then position.
  • A camera has a position, a yaw and a pitch. The eye sits viewDistance behind a plane at that position, so things on that plane keep their size. Lines nearer the eye than nearDistance are cut off, so objects can pass the camera.

A whole program

The examples above are given a display list and a clock. This is everything a real page needs: a canvas, a renderer, the phosphor, and a frame loop. It is not editable here, because it is the part this page is already doing for every example. 

import { DisplayList, Shape } from "@vector-display/core";
import { WebGLVectorRenderer } from "@vector-display/webgl";
import { PhosphorPipeline } from "@vector-display/beam-fx";

const canvas = document.querySelector("canvas");
const pixelRatio = Math.min(2, window.devicePixelRatio || 1);
canvas.width = canvas.clientWidth * pixelRatio;
canvas.height = canvas.clientHeight * pixelRatio;

// The world is 1024 by 768 units, whatever size the canvas is.
const renderer = WebGLVectorRenderer.fromCanvas(canvas, { width: 1024, height: 768 });
renderer.setLineStyle({ beamWidth: 1.5 * pixelRatio, glowRadius: 3 * pixelRatio });
const phosphor = new PhosphorPipeline(renderer, {
  persistenceHalfLifeMilliseconds: 60,
  bloomStrength: 0.6,
});

// Build shapes once.
const ship = Shape.fromPolyline({
  points: [{ x: 0, y: -10 }, { x: -7.5, y: 10 }, { x: -5, y: 5 }, { x: 5, y: 5 }, { x: 7.5, y: 10 }],
  isClosed: true,
});
const displayList = new DisplayList();

let previousTime = performance.now();
function drawFrame(time) {
  displayList.clear();
  displayList.setColor({ red: 0.85, green: 0.95, blue: 1 });
  displayList.addShape(ship, { x: 512, y: 384, rotation: time / 1000, scale: 4, intensity: 1 });

  // In place of renderer.clear() and renderer.drawDisplayList(displayList):
  phosphor.renderFrame(displayList, time - previousTime);
  previousTime = time;
  requestAnimationFrame(drawFrame);
}
requestAnimationFrame(drawFrame);

Without the phosphor, the loop is renderer.clear() followed by renderer.drawDisplayList(displayList). Drawing is additive and goes to whatever framebuffer is bound, so the renderer can also draw into a texture of your own.

Reference

All five packages are ES modules with TypeScript declarations, at version 0.1; the API may change between minor versions.

PackageExports
@vector-display/core Shape, DisplayList (clear, setColor, addShape, getSegmentData, segmentCount), SCREEN_SPACE_PLACEMENT, NO_NEIGHBOR_SEGMENT, and the types BeamColor, Polyline, ShapeGeometry, ShapePlacement. No rendering code, so it runs in Node and in tests.
@vector-display/webgl WebGLVectorRenderer (fromCanvas, setWorldSize, setLineStyle, clear, drawDisplayList, dispose), DEFAULT_LINE_STYLE, createShaderProgram. Needs WebGL2.
@vector-display/beam-fx PhosphorPipeline (renderFrame, setSettings, dispose), DEFAULT_PHOSPHOR_SETTINGS.
@vector-display/font VectorFont (createArcadeFont, fromDefinition, addText, measureText, hasGlyph, findGlyph), ARCADE_GLYPHS, ARCADE_FONT_METRICS.
@vector-display/3d WireframeModel, WireframeProjector (project, setCamera), createBoxModel, createPyramidModel, createModelPlacement, DEFAULT_PERSPECTIVE_CAMERA. Uses es-vector-math.

The rest of this site is built on the same five packages. The demos are the larger examples: each one is a few hundred lines that fill a display list every frame.
